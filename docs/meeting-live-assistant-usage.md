# 实时会议助理 — 使用指南

> Iris 3.26.0 · 会议中实时转写 + 逐段提炼要点/风险/问题/决策点 + 提示关键提问 + 话题追踪 + 说话人区分 + 实时洞察推送，过程实时写入按话题结构的 Markdown 文档，退出时自动生成 AI 会议总结。v3.26.0 新增：本地音频 ASR（无 vocotype 依赖）、洞察推送、热键交互、说话人区分、话题去重、按话题文档。

## 快速开始

```bash
# 1. 启动会议助理（保持终端在前台）
iris meeting-live-assistant

# 2. 直接对着麦克风说话（无需按键），说完停顿 1.5s 自动识别
# 3. 系统自动：转写 → 校正 → 知识库检索 → 批量分析 → 面板实时更新 + 洞察推送
# 4. Ctrl+C 结束会议：生成会议总结 → 打印统计帧（含发言统计），过程文档已完整
```

> ✅ **与 asr-corrector 可同时运行**（v3.25.0 起使用本地麦克风，无剪贴板依赖，不再互斥）。

## 命令

```bash
iris meeting-live-assistant                          # 默认输出 data/meeting-live/YYYYMMDD-HHMMSS-会议记录.md
iris meeting-live-assistant --output ~/会议.md       # 自定义路径（可指到 SOURCE 目录归档，自动带 frontmatter）
```

## 前置条件

- **麦克风权限**：macOS 偏好设置 → 安全性与隐私 → 麦克风 → 终端已勾选（未授权时 5 秒后提示）
- **ASR 模型**：首次运行自动从 ModelScope 下载（~913MB），或复用 vocotype 已下载缓存；也支持 `assistant.asr.local.model_dir` 指定
- Iris 已配置 LLM（`.env` 中的 API Key）与知识库（检索上下文，缺失时自动降级为无上下文分析）

## 配置（config/app.json）

```jsonc
"assistant": {
  "output_dir": "",             // 过程文档输出目录（默认 data/meeting-live/，--output 参数优先）
  "top_k": 5,                   // 每段知识库检索条数
  "llm_model": "",              // 段分析 LLM 模型（空=走全局路由）
  "poll_interval": 0.5,         // 段轮询间隔（秒）
  "doc_rewrite_every": 1,       // 每 N 段重写文档（1=每段）
  "short_segment_chars": 15,    // 短段门控：短于该长度视为确认语，跳过 LLM（零成本排空流水线）
  "max_segment_chars": 2000,    // 单段长度上限（超长丢弃并警告；默认覆盖 120s 长语音）
  "suggest_every": 3,           // 建议提问生成间隔（每 N 段一次，省 token 减重复噪音）
  "summary_enabled": true,      // 退出时生成 AI 会议总结（失败自动跳过）
  "agenda": "",                 // 预设议题（分号分隔，如 "售后归拢;QA指标统一"）——注入分析并跑偏提醒
  "save_knowledge": false       // 退出时回写知识库（预留，暂未实现）
},
"asr": {
  "mode": "local",
  "local": {
    "model_dir": "",            // 模型目录（空=自动检测 ~/.cache/modelscope）
    "device": "cpu",
    "sample_rate": 16000,
    "energy_threshold": 0       // VAD 能量阈值（0=自动适应噪声地板；0.001-0.05 固定）
  },
  "hotwords_file": "data/assistant/asr_hotwords.txt",     // 热词（每行一个词条）
  "replace_dict_file": "data/assistant/asr_replace_dict.json",  // 音近词映射（AC 词典）
  "llm_correct_enabled": true,
  "llm_correct_timeout_ms": 8000
}
```

**路径优先级**：`--output` > `assistant.output_dir` > `data/meeting-live/YYYYMMDD-HHMMSS-会议记录.md`

## 工作链路

```
说话 → sounddevice 麦克风采集（16kHz）→ VAD（40ms 帧级判定，静音 1.4s 切段）
  → 噪音门控（复读/英文碎片/单字拦截）→ merge buffer（内容感知 + 说话人边界，≤3s 窗口合并）
  → AC 词典校正（毫秒级，立即显示）→ 提交 LLM 深度校正 ∥ 知识库检索（futures）
  → 批处理（最多 5 段 / 2s）：合并文本一次 LLM 分析（要点/风险/问题/决策/建议提问/话题/说话人/待办）
  → 话题追踪 + 冲突检测 + 说话人登记 + 洞察推送
  → 终端面板 + 按话题结构化文档原子重写
  → Ctrl+C：等当前批完成 → AI 会议总结 → 统计帧 → 文档最终写
```

**短段门控**：确认语（「好的」「嗯」等，<15 字）跳过全部 LLM 直接落账，面板/文档显示「⏭ 跳过分析」。

**积压策略**：说话快于分析时只处理最新批（中间段丢弃，面板显示「积压丢弃 N 段」），保证追得上会议节奏。

**降级链**：LLM 不可用 → 仅词典校正 + 面板/文档显示「分析不可用」，会议不中断；模型调用超时自动降级（flash → pro → 百炼），连续失败 2 次熔断 60s 后自动恢复。

**热键**（会议中直接按键）：

| 按键 | 功能 |
|:---:|------|
| `?` | 显示帮助 |
| `d` | 显示已确认决策（✅） |
| `t` | 显示当前话题 / 已讨论话题列表 |

| `q` | 优雅退出（等同 Ctrl+C） |

**洞察推送事件**：✅ 决策确认 / 📌 话题切换 / ⚠ 风险 / 🔥 语义冲突 / 📋 待办 / 🗣 说话人切换。

## 说话人区分

系统通过 LLM 语义推断区分说话人（不依赖声纹）：
- 段标题、面板状态后缀显示 `speaker_A` / `speaker_B` 及角色提示（主持人/汇报人/提问者）
- VAD 检测到可能切换时（停顿 >0.8s）不合并不同人的发言
- 退出统计帧显示各说话人发言段数
- 会议记录中决策标注拍板人

## 过程文档（按话题结构化）

每批处理完立即写入，**会后直接可用**（退出时全量渲染为话题结构）：

```markdown
---
title: 实时会议记录 2026-08-12 12:00
type: 实时会议记录
source: meeting-live-assistant
---
# 实时会议记录 2026-08-12 12:00
**概览**：8 个话题 · 30 分钟 · 5 决策 · 3 待办 · 12 风险

## 📌 话题 1：售后归拢到校（段 1-28）
**讨论**：提出中仓售后归拢到校需求…
**决策**：✅ 先介绍方案，不满足再联动解决

## ✅ 决策汇总 / 📋 待办汇总 / ⚠ 风险汇总
## 📝 会议总结（AI 生成）         ← Ctrl+C 退出时生成
## 📎 附录：完整逐段转写（折叠）   ← <details> 展开查看
```

- 原子写入（唯一 tmp + rename + 锁）：进程中断不损坏旧文件
- 话题自动聚合：同一讨论的不同措辞标签自动去重（2-gram 语义合并）
- 归档知识库：`--output` 指到 SOURCE 目录（如 `05-会议纪要/`）即带 frontmatter
- 需要正式纪要时事后另跑 `transcribe-meeting`（本功能只做过程记录）

## 常见问题

**Q: 启动后 5 秒无响应？**
A: 检查 macOS 麦克风权限：偏好设置 → 安全性与隐私 → 麦克风 → 终端已勾选。

**Q: 第一次运行要下载什么？**
A: Paraformer 模型 ~913MB 自动下载到 `~/.cache/modelscope/`，后续秒加载；可配置 `assistant.asr.local.model_dir` 指定已有缓存。

**Q: 说话后面板没有新段？**
A: 检查：① 麦克风是否被其他 App 占用；② 是否说得太轻（VAD 阈值自动适应，环境噪声大时可调低 `energy_threshold`）；③ 若被噪音门控拦截（复读/英文碎片）会静默丢弃。

**Q: 分析总显示「分析不可用」？**
A: LLM 调用失败或超时（检查 API Key/网络），已降级为词典校正原文，会议不中断。降级链会尝试 flash → pro → 百炼。

**Q: 面板「积压丢弃 N 段」是什么？**
A: 说话快于分析时自动只处理最新批，保证实时性；丢弃段原文保留在文档附录 `<details>` 中可追溯。

**Q: 说了一长段（1 分钟以上）后面板没反应？**
A: 检查是否超 `max_segment_chars`（默认 2000 字）——超长会警告。更短的停顿分段说效果最好。

**Q: 话题太多太碎？**
A: v3.26.0 已做语义去重（同一讨论的不同措辞自动合并）。若仍嫌细，可在 `suggest_every` 或分析 Prompt 中调整。

**Q: 能和其他语音工具同时用吗？**
A: 可以。本地麦克风采集不占用剪贴板，与 `asr-corrector` 互不冲突。
