# 声笺 · Iris Caption：需求与技术设计草案

状态：开发预览实现中；核心界面与服务已实现，真实会议及最低配置验收未完成。
日期：2026-11-05

产品命名（已确认）：

- 应用显示名称：**声笺**。
- 英文名称：**Iris Caption**。
- 完整名称：**声笺 · Iris Caption**；关于页面注明 *by Iris*。
- 仓库子项目名：`iris-caption`。
- 命令及内部标识前缀：`iris_caption`。
- 在 Iris 仓库内维护，但作为独立 macOS 应用安装和运行。

## 1. 产品目标

提供独立安装、双击启动的 macOS 会议字幕应用。持续收音，无需按住录音快捷键；本地生成实时或准实时字幕，通过领域词典及云端 LLM 校正。初步转写优先快，校正结果优先准确，校正不得阻塞转写。

目标环境：Apple Silicon，最低 M1 / 8GB。个人在多台 Mac 使用。主要为 2–10 人线下会议，收音距离约 1–4 米，大型会议偶发。主要使用内置麦克风，偶尔外接会议麦克风，需要设备选择。通常连续使用 1–2 小时，最长按 4 小时验证。

首版不包含：说话人区分、录音保存、实时翻译、自动生成会议摘要。

## 2. 已确认功能

### 2.1 转写与校正

- 中文为主，支持夹杂英文术语、缩写、项目名。
- 边说边显示初步转写，约 1–2 秒为目标，具体分位指标与测量方法见验收章节；当前不宣称已达到。
- 原文在识别中允许增量更新，ASR 定稿后保留；校正版本独立展示。
- 校正采用本地替换词典及云端 DeepSeek，具体云端模型版本在实现前核实。
- 保守轻度润色：纠正有依据的错字、人名、术语、标点，清理无意义填充词和机械重复。
- 保留否定、犹豫、强调、自我修正、数字、时间、责任人及原意；不跨句合并，不做摘要，不确定时保留原文。
- 参考最近 3–5 个已定稿句段和少量相关资料片段；数量及输入长度上限后续调优。只输出当前句段校正结果。
- 云端失败不阻塞本地转写；标记待校正，恢复后优先最新句段，再补齐积压。

### 2.2 界面

- 独立窗口，当前字幕和可滚动历史。
- 默认原文在上、校正在下；可切换双列。原文与校正不同配色，同时保留文字标签。
- 双列按句段对应，行高由较长一侧撑开，统一滚动；不使用两个独立滚动文本框。
- 支持字号调整、大字号全屏投屏。
- 投屏默认单份字幕：先原文、后原位更新为校正结果；可切换对照。
- 查看历史时停止自动滚动，提示新字幕；点击“回到实时”恢复跟随。
- 可编辑校正结果，原文不变；人工修改不得被迟到的自动结果覆盖。
- 修改后提取候选替换规则，用户确认后才能加入；可选仅本场或本机长期。

### 2.3 会议背景与资料

- 可选填写主题、参会人、项目；不填可直接开始。
- 支持粘贴文字、本地文件及飞书文档。本地文件首版拟覆盖 Markdown、TXT、PDF、DOCX；扫描件 OCR 范围待实现前明确，不默认视为已支持。
- 飞书由应用直接使用用户身份授权，读取用户有权限的文档；凭据存入钥匙串。
- 会前、会中均可新增或更新资料，只影响后续句段，不自动重校历史。
- 本地轻量向量检索结合关键词检索，索引构建低于音频转写优先级。
- 允许向云端发送少量相关正文片段及术语，不默认发送全文。
- 资料默认仅本场临时使用，可选择长期保留。长期资料可查看、删除；复用飞书资料时检查权限和更新。

### 2.4 保存与隐私

- 会议记录默认不自动持久化，首版仅手动保存文字，不保存录音。
- Markdown 导出包含时间戳、ASR 原文及校正结果。
- SRT 导出可选原文、校正结果或双行对照，默认校正结果；未校正句段回退为原文。
- 有未保存内容时退出，提供保存并退出、不保存退出、取消。
- 音频仅在本机处理，短时内存缓冲用于识别，不录制为会议音频文件。
- 默认会议文字、临时资料索引及校正队列仅在内存；文件解析确需临时文件时受控清理，异常退出残留在下次启动清理。不得在诊断日志记录音频、全文、密钥或正文片段。
- 明确选择的长期资料、长期规则、模型和偏好设置可持久化，与会议记录保存分开。
- 各 Mac 分别配置 DeepSeek API Key，存入 macOS 钥匙串。

## 3. 架构决策

### 3.1 仓库与进程

在 Iris 仓库内维护独立应用，独立打包；只共享必要代码和知识接口，不要求运行完整 Iris。

- PySide6 主进程：窗口、字幕状态、用户操作与展示。
- 独立 Python 音频/识别进程：采集、重采样、VAD、音频缓冲、ASR。
- 后台任务：LLM 校正、资料读取与索引、导出；不得在 GUI 线程执行阻塞工作。索引是否独立进程根据资源测试决定。
- 建议以本地进程通信传递结构化事件；不开放对外网络服务。具体采用管道或本地 socket 为实现选择。

界面与核心链路并行开发，使用统一事件协议和模拟事件源联调。

### 3.2 ASR 选型

优先调查用户当前 VocoType 的 contextual Paraformer 模型。用户提供名称为 `platformer-large-zh-cn-contextual`，疑为 `paraformer-large-zh-cn-contextual`；准确模型 ID、版本、量化方式、运行框架均待核实。

不得将 contextual 热词增强等同于流式能力。优先验证该模型的单模型滚动短窗口方案，测试延迟、重复计算、边界漏字和字幕变化。未达到目标时比较真正流式模型，或流式初稿加 contextual 定稿方案。双模型不可在未测量前承诺适合 M1 / 8GB。

适配器统一输出临时结果、稳定原文和句段时间信息，不向界面暴露特定模型协议。英文术语、热词注入、时间戳及分发许可均需按具体模型核实。

### 3.3 切段与时间

停顿优先，最长时长兜底。起始调优值为停顿 0.6–0.8 秒、最长句段 10–15 秒，均不是已验证参数。

初稿不断更新，停顿或上限触发定稿。强制切段保留适当音频上下文，并验证跨段去重和漏字；不能直接拼接重叠窗口的所有文字。

采用音频采样位置建立统一时间轴，时间戳不以 LLM 完成时刻生成。SRT 首版使用句段级时间戳，不承诺字级对齐。暂停、恢复及设备切换的时间轴规则需在实现时统一。

### 3.4 句段状态与异步一致性

建议每个句段至少包含：

- session_id、segment_id、起止时间、revision。
- partial_text、final_raw_text、dictionary_text、corrected_text。
- ASR 状态、校正状态、错误类别、人工编辑标记。
- 使用的会议背景版本、知识包版本、规则版本。

所有异步结果携带 session_id、segment_id 和 revision。结果只有在会话、版本和人工编辑状态仍匹配时才能应用。新会话不得收到旧会话结果。

建议状态：转写中 → ASR 定稿 → 等待校正 → 已校正；另有可重试失败、人工编辑、已取消状态。

背景更新以句段定稿入队为版本边界；补校正仍使用该句段绑定的背景快照，不因新资料自动改写历史。人工规则按同样原则绑定版本。

### 3.5 校正调度

- 识别与校正队列分离，网络请求不得反压音频采集。
- 有界并发、请求超时、限流退避；新字幕优先，历史任务逐步补齐并避免永久饥饿。
- 待校正队列仅保存文本和必要引用，不保存音频；任务按句段去重。
- 用户人工编辑、结束会话或退出时取消不再适用的任务。
- LLM 输出保留输入内容语义，拒绝空内容、解释性回答及明显异常输出；校验阈值需结合会议样本测试，不机械沿用口述相似度阈值。
- 资料片段视为参考数据，不能成为覆盖校正任务的指令。

## 4. Iris 知识包

内容只包含热词、替换词典、校正规则、领域保护名单和来源版本信息，不携带 SOURCE/Wiki 全文。

建议结构：manifest、hotwords、replacements、prompt/rules、protected_terms。manifest 包含 schema_version、package_version、生成时间、来源标识及文件校验和；避免导出本机绝对路径、密钥和无关个人信息。

导入时校验 schema、完整性与内容格式，拒绝路径穿越和超出限制的文件。完成校验后原子切换新版本，失败保留旧包。

三层规则独立存储，优先级：本场会议 > 本机长期 > Iris。冲突可查看、调整，更新知识包不得覆盖人工规则。

知识包跨设备同步机制尚未确定。首版可先定义导入接口，不能把共享目录、网络服务或自动同步视为已确认要求。

## 5. 资料与飞书

资料解析输出带来源的文本块，本地构建关键词和向量索引。对检索结果设数量与字符预算；同名人名、项目词不能仅凭模糊相似度强制替换。

向量模型应轻量、适合中文夹英文，具体型号、许可证、内存与索引性能待评估。索引任务需限并发，必要时暂停以保障转写。

飞书接入需验证应用类型、用户 OAuth、所需权限、刷新凭据、撤权和文档可见性。不得在桌面安装包嵌入可复用的服务端应用密钥；如授权方案需要服务端保密凭据，需重新讨论授权中转或用户自配方案，而不是默认为桌面端安全存储即可。

来自敏感 SOURCE 文档的派生信息仍须遵守 Iris 现有敏感文档过滤规则；通用知识包沿用现有管道的过滤边界。

## 6. 安装、资源与持久化

- 首版个人使用 DMG 或 ZIP，手动安装，暂不做 Apple 公证；Gatekeeper、麦克风权限和钥匙串行为必须在另一台 Mac 验证。
- 内含所需运行环境，不要求用户安装 Python 或使用终端。
- ASR 和向量模型首次下载，支持进度、失败重试、手动导入；固定兼容版本和校验和。
- 不承诺直接使用 VocoType 模型缓存，先核实格式、版本和许可，避免修改其文件。
- 共享持久状态读改写使用文件锁，单文件原子写，多文件版本目录原子切换；数据库等资源显式关闭。
- 按现有项目约定评估 TaskReporter：不为独立应用引入完整 Iris 依赖，若不接入需在实施记录说明，应用自身提供阶段及健康状态。

## 7. 实施计划

以下为建议阶段，尚不表示已经开始实施。

### 阶段 1：并行建立界面与核心验证链路

界面：独立窗口、模拟句段事件、双行/双列、配色标签、自动滚动及投屏。
核心：核对 VocoType 模型、M1 / 8GB 基准、持续收音、设备选择、VAD、增量识别、时间轴与队列。
共享：消息协议、句段状态、版本校验、错误状态。

退出条件：能演示连续字幕；具备初步性能数据，确定保留或调整 ASR 方案。

### 阶段 2：校正与知识

接入词典、DeepSeek、上下文、人工修改、候选规则、Iris 知识包、重试补校正。

退出条件：乱序/超时结果不会覆盖人工编辑，云端不可用不影响转写，规则优先级符合设计。

### 阶段 3：资料、授权与导出

资料解析与本地检索、飞书授权、背景版本管理、资料保留选项、Markdown/SRT、未保存退出提示。

退出条件：权限及删除行为可验证，导出内容与界面对应，无默认会议正文持久化。

### 阶段 4：打包与真实验收

模型下载/导入、独立安装包、另一台 Mac 安装、多应用共存测试、真实会议片段对比及 4 小时稳定性测试。

## 8. 验收与证据

区分已确认目标与待实测门槛，不以演示成功替代长时间验证。

| 项目 | 验证内容 |
|---|---|
| 初步字幕延迟 | 以音频时间为基准记录首次文本、稳定原文和校正结果的时刻，报告 P50/P95；目标约 1–2 秒，最终分位门槛根据基准提出 |
| 定稿与校正 | 分别报告切段等待、ASR 耗时、队列等待及 LLM 耗时；校正不得阻塞原文 |
| 识别质量 | 同一音频比较候选方案；人工标注片段计算中文字符错误率，单独统计人名、术语、数字、否定词 |
| 校正质量 | 统计正确修复与误改，重点检查否定、自我修正、数字、时间、责任人；比较校正前后 |
| 边界处理 | 长时间无停顿、短停顿、重复词、跨段术语、静音、背景噪声、插话；明确多人重叠的能力限制 |
| 最低设备 | M1 / 8GB，记录总内存、各进程占用、CPU、系统内存压力和交换；同时运行常用应用 |
| 长时间稳定性 | 连续 4 小时，检查音频丢帧、队列积压、内存持续增长、时间轴漂移及界面响应 |
| 故障恢复 | 断网、超时、限流、密钥无效、设备拔出、模型缺失；无错误覆盖、无静默停止 |
| 数据与隐私 | 默认不落盘会议全文/音频，钥匙串保存凭据；临时文件清理，明确保存内容可删除 |
| 分发 | 无开发环境的另一台 Apple Silicon Mac 安装、权限授予、模型导入和导出完整通过 |

样本采用通用音频和用户认可的真实会议片段。ASR 验证音频本地处理；云端校正仅使用授权范围内的文字及上下文。

## 9. 开发前需调查但不预先定案的事项

1. VocoType contextual 模型准确身份、运行后端、量化及许可；非流式滚动窗口能否满足目标。
2. 轻量向量模型、与 ASR 同时驻留的资源预算。
3. 飞书桌面用户授权的可实施方案及是否需额外服务端。
4. PySide6 与推理依赖在 macOS arm64 的打包、许可和权限验证。
5. 会议资料文件大小限制、扫描 PDF 处理范围；不支持时应明确提示。
6. Iris 知识包跨设备同步方式暂缓，不影响先设计知识包协议。
