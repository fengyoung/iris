# v3.40.7 全量优化第一阶段

本轮优化围绕数据正确性、长任务资源边界和运行可观测性展开，保持现有 CLI、Web 和复盘格式兼容。

## 已完成

### Wiki 增量正确性

人物页批量更新现在可以检测页面生成后新增的成员周报。检测通过源文档 hash 索引中的 `modified_at` 与页面 `updated` 时间比较，并限定为 `-{人物姓名}.md` 文件，避免一份新文档导致所有页面重新调用 LLM。旧调用方默认保持原有指纹语义。

### 任务预算

新增 `iris.taskpanel.budget.TaskBudget`，支持：

- 最大运行时间
- 最大调用次数
- 最大输入/输出 token
- 最大估算费用

调用方在外部调用前使用 `check()`，完成后使用 `record()`。超过任一上限会抛出 `TaskBudgetExceeded`，由上层决定终止或保存部分结果。

### 任务可观测性

`TaskStatus` 新增兼容字段：

- `trace_id`
- `elapsed_seconds`
- `llm_calls`
- `input_tokens`
- `output_tokens`
- `estimated_cost`

旧的 current/history JSON 缺少这些字段时仍可正常读取。`TaskReporter` 提供 `check_budget()` 和 `record_usage()`，后续长任务可逐步接入，不要求一次性改动全部业务模块。

## 后续接入顺序

1. 谁是卧底 Web 对局：按玩家数和最大轮数建立调用次数预算。
2. Wiki 批量更新和深度评估：增加时间、并发和费用预算。

## v3.40.8：覆盖率驱动的核心行为治理

本阶段根据实测覆盖率补强报告生成、深度评估、Wiki 生成的集成测试。模型调用使用确定性替身，文件、缓存和页面备份使用真实临时目录；不访问个人知识库，不调用付费模型。

修复了以下经旧实现复现的缺陷：

- 摘要正文后 2,000 字或方向分配改变，缓存仍被错误复用。
- 同名方向的目标或责任人改变，Stage 1 筛选缓存没有失效。
- 预览模式在 OP 缓存未命中时调用模型。
- `inconsistent` 被子串匹配误判成 `consistent`。
- 无描述引用的页面级校验被自身非空描述条件阻断。
- 已引用的第二份及后续来源仍被作为遗漏候选处理。
- 无效 Wiki 更新被拒绝后仍刷新新证据指纹。

三个核心模块新增 70% 独立覆盖率门槛。测试提升的是程序行为的可验证性；真实模型的事实准确率、检索质量仍需真实样本评测，不能由语句覆盖率推断。

预算对象仍是第一阶段的可选 API，本次只补齐其现有边界测试，不宣称已接入全部长任务。

- 任务预算：90% → 100%。
- 13 个关键模块覆盖率门禁、Ruff、mypy（193 源文件）、AST 安全扫描全部通过。
