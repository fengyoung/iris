# 谁是卧底 Web 界面使用说明

> v3.39.0 新增功能。基于 `iris undercover-game-web` 命令启动本地 Web 服务，无需额外依赖。

---

## 快速启动

```bash
iris undercover-game-web
```

服务默认监听 `http://127.0.0.1:7862`，浏览器打开即可使用。

可选参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--port` | 7862 | 监听端口 |
| `--host` | 127.0.0.1 | 监听地址 |

```bash
# 示例：指定端口
iris undercover-game-web --port 8080
```

按 `Ctrl+C` 停止服务。

## 界面说明

Web 界面包含四个视图，通过顶部导航栏切换。

### 1. 游戏设置

**参与模型**

默认列出 `config/llm.json` 中全部支持多模态的模型（`base_model` 与 `adv_model` 两组），勾选即为玩家。标题栏有 **全选 / 全取消** 两个按钮，便于批量操作（跳过被裁判占用的模型）。

- 至少需要 3 名玩家，最多 12 名
- 同一 `role/model_id` 组合不能重复出现
- 被裁判占用的模型**禁用并置灰**，标注「· 裁判」——与裁判互斥，见下

**选择会被记住**：点击「开始游戏」时把玩家勾选、裁判模型、卧底数、发言顺序与运行模式存入浏览器 `localStorage`（键 `undercover-setup`），下次打开自动恢复，不必每次从头配置。恢复后仍会重新执行裁判互斥。清空该键即回到默认全选。若模型列表有变动，已下线的模型自然落空、不再勾选。

若模型列表读取失败，会退化为「手动」模式：每行选择角色（`base_model` 或 `adv_model`）与对应模型 ID。

**游戏图片**

分别上传平民图片（图片 A）和卧底图片（图片 B），支持点击选择或拖拽上传。两张图片必须不同。

支持格式：JPG、PNG、GIF、WebP、BMP。

上传约束：单文件不超过 20 MB，像素不超过 6400 万（上限只为挡住「小文件谎报超大尺寸」的解码炸弹，正常手机与相机照片远在其内）。

上传后服务端会把长边缩到 2048px 以内再落盘——视觉模型本就会把图缩到这个量级再计费，实测 `qwen3.8-max-zz` 的图像 token 在长边 2048px 触顶、更大尺寸不增加信息量。**只缩不放**：未超限的图片原样保存，不重新编码。因此预览、模型输入与复盘看到的是同一张图，复盘还原的就是模型实际看到的画面；原始图仍保留在本机。缩放后长边仍超限的 BMP/GIF/WebP 会转存为 PNG（无损），扩展名随之变更。

**游戏参数**

| 参数 | 说明 |
|------|------|
| 卧底数量 | 默认 1，需小于玩家数的一半 |
| 发言顺序 | 每轮轮转（默认）或固定顺序 |
| 随机种子 | 留空则每局随机，填数字可复现同一对局 |
| 运行模式 | **自动**：游戏全程自动运行；**手动步进**：每轮结束后等待点击"下一轮"才继续 |

**玩家编号**

每位玩家有一个**全局固定编号**（`player_number`，开局分配、淘汰后不重排），界面上显示为「N号」。模型侧的一切玩家引用也统一写成 `N号=role/model_id`——描述、历史记录、存活名单、投票候选都用这一种写法，模型写编号或写完整 key 都能被精确解析。

要注意它**不是发言位次**：发言顺序在开局随机打乱、每轮起点顺延，所以「本轮第几个发言」每轮都变，而固定编号不变。历史记录的行首 `1.` 才是本轮位次，紧随其后的 `N号=` 是固定编号，两者刻意并存以免混淆。

**对局策略**

模型事先都不知道自己的身份，只能从他人的公开描述里推断；提示词据此给出条件化的行动准则，对全部玩家逐字相同（身份只体现在各自拿到的图片上）：

- **目标随推断出的身份切换**：判断自己属多数派 → 找出并投出卧底；判断自己属少数派 → 活到最后。判断不确定时按多数派方式说话——含糊其辞本身就是异常信号。
- **身份判定看两条并列证据**：① 主体矛盾（自己看到的主体元素几乎无人提及）；② **属性冲突**（多数人反复提到某属性 A，自己看到的是与 A 互斥的 B）。第二条是 2026-09-16 复盘补上的——那局卧底的主体元素（人物、发型、背景）与所有人对得上，只有服饰互斥，旧口径把它排除在外，于是它自评「平民 96%」，进而按平民目标当众纠正他人，一轮即出局。
- **首位发言者给锚点、不亮底牌**：本局第一位发言的人没有任何可比对内容，应给出一两个**可核对**的中性锚点（人物、场景类别、背景），但不展开最具体的辨识特征、也不主动质疑。早先只要求「少说细节」，实测导致首位发言给出零信息的描述，整轮无从比对。
- **少数派的隐蔽手法**：取舍、概括、借用共享词、措辞模糊化、转移视线（均须真实，不得编造或凭空指控）。
- **少数派看到真实差异时的出路**：若判断自己是少数派、而对方描述与自己所见图确实对不上，**既不指出也不附和**，改为只回应双方都成立的中性元素。规则要求「质疑必须基于真实内容」，卧底照做即自曝——所以在质疑条里另行留出口：只在这个矛盾连自己也认同时才质疑。
- **同类识别但不结盟**：少数派可从「他的描述与我自己那张图相符」推断出同类，并据此不把质疑与投票指向对方、把注意力引向其他人的真实差异。**识别纯靠推断，严禁任何形式的示意、试探或回应信号**——保留这条是为了不破坏「玩家不知自己身份」的前提，否则平民也能反向伪装成卧底把水搅浑。
- **禁止整段复述**：借用共享词可以，但描述里至少要有一项自己独立观察到的元素。与「防装死」同源——无信息的发言不该是零成本的隐身术。

**裁判模型**

负责每轮增量校验与对局总结，固定以 `base_model` 角色调用。默认 **`deepseek-flash`**（官方直连通道），可在输入框中改成任意模型 ID。

**每局都会产出总结**：结算时由该模型异步生成 `summary.md`，写入复盘目录。**被主动终止的对局同样出总结**——已跑完的轮次仍有分析价值，复盘里以 `winner=cancelled` 标明这是部分复盘；只有在拿不到裁判模型标识时才会跳过。

**与玩家模型互斥**：裁判所在的模型不能同时作为玩家。选中的裁判模型会在玩家列表中禁用并取消勾选，改裁判后旧裁判恢复可选。这条约束由前端禁用与后端校验双重保障——前端只是交互约定，直接构造请求同样会被拒。

### 2. 观战视图

游戏开始后自动进入观战视图，实时通过 SSE 接收并展示游戏事件。

**顶部状态栏**

显示当前轮次、阶段（描述中 / 投票中 / 已结束）和控制按钮。

**玩家状态栏**

横向排列所有玩家卡片，每位玩家有独立颜色，淘汰后显示划线与 ☠ 标记。

**时间线**

新事件从底部追加，自动滚动。事件分为四种类型：

| 类型 | 样式 | 内容 |
|------|------|------|
| 🔒 思考卡 | 玩家色淡化背景 + 斜体 + "仅观战者可见" | 观察清单（可折叠）、身份自评、置信度、判断依据 |
| 描述卡 | 玩家色左边框 + 白底 | 公开描述 + 回应 |
| 投票卡 | 玩家色淡化左边框 | 投票目标 + 原因 |
| 裁判陈述 | 灰底无色条 | 轮次开始/结束、淘汰通知、游戏结束横幅 |

> **注意**：思考内容是各模型的私有档案，游戏引擎保证模型之间不互相可见（不进入其他模型的 prompt），但观战者可以看到全部思考以获得完整的观战体验。

**手动步进模式**

运行模式选择"手动步进"时，每轮结束后"下一轮"按钮变为可点击状态，游戏等待用户确认后才进入下一轮。

**终止**

点击"终止"按钮立即停止游戏并返回设置页。

---

### 3. 历史对战列表

展示所有已完成的对局，按时间倒序排列，显示日期、胜负、玩家数、卧底数和是否有裁判总结。

点击任意对局进入复盘详情。

---

### 4. 复盘详情

**图片对比**

并排展示本局使用的平民图片和卧底图片，以及最终胜负结果和全部玩家（含身份标注）。

**裁判总结**

游戏结束后由裁判模型异步生成，内容包括：
- 对战概览
- 关键转折点分析
- 各模型表现点评
- 裁判总评

若总结尚未生成完成，显示"生成中"提示，刷新页面可查看最新状态。

**轮次折叠**

点击展开任意轮次查看完整的描述、投票记录，与观战时的时间线样式一致。

**显示私有思考**

复盘默认不展示私有思考（模拟当时观战视角），点击"显示私有思考"切换，展开的轮次会立即重新渲染。

**导出 JSON**

下载完整的 `replay.json`，包含全部私有思考字段，可用于离线分析。

## 数据存储

每局对局数据存储于 `data/games/<game_id>/`：

```
data/games/
├── uploads/                    ← 上传图片暂存区
└── 20260915-143022-a3f7/       ← 单局目录（时间戳+4位随机码）
    ├── civilian.<ext>          ← 平民图片副本
    ├── spy.<ext>               ← 卧底图片副本
    ├── replay.json             ← 完整对局记录（含私有思考）
    └── summary.md              ← 裁判 LLM 总结（异步生成）
```

`replay.json` 包含完整的每轮发言、投票、私有思考和最终结果，可供离线复盘或脚本分析。

## 与 CLI 命令的关系

Web 界面是 `undercover-game` CLI 命令的图形化前端，底层使用相同的 `UndercoverGame` 引擎。CLI 命令不受影响，两种方式可以并行使用。

```bash
# CLI 方式（不变）
iris undercover-game --image-a civilian.jpg --image-b spy.jpg \
  --game-models "base_model/claude-sonnet,adv_model/qwen3.8-max,base_model/deepseek-flash"

# Web 方式（新增）
iris undercover-game-web
```

## 交互优化说明（v3.40.1，合并 0916-beta）

- 顶栏的“当前对局”支持刷新后恢复观战；若服务已重启，尝试打开保存的复盘。SSE 自动重连时展示连接状态。事件已过期时停止消费并等待复盘保存。
- 对局结束先显示“正在保存复盘”，保存完成后提供本局复盘入口。终止为协作取消，可能需要等待正在执行的模型请求返回；页面保留取消进度，不再立即返回设置。
- 手动模式只有真正等待下一轮时才能推进；已判胜负或达到轮次上限不会再等待。重复或过期的推进请求返回状态冲突。
  注意**人数打平的轮次不算「已判胜负」**（v3.40.4 起胜负判定为严格多数），该轮照常进入等待态——
  引擎侧由 `continuing` 判定发 `round_waiting`，与胜负判定严格互补；两者一旦不同步，
  这一轮的步进会被静默跳过（对局照跑、界面不报错）。
- 玩家使用固定编号（1号、2号等，取 `player_number` 全局编号，淘汰后不重排）。时间线支持公开信息、事件类型、玩家筛选与自动跟随开关；“跳到最新”不修改筛选。
- 复盘总结区自动每 5 秒更新，明确区分生成中、已完成、失败和未启用。只更新总结区，保留轮次展开状态。
- 历史对局支持模型、ID、种子搜索以及日期、结果筛选；取消对局明确标记为部分复盘。
- 角色组不等同于能力保证：标记为多模态只表示配置如此，启动时模型连接失败仍会显示运行错误。
- 裁判与玩家模型互斥；裁判固定以 `base_model` 角色调用，故 `base_model/X` 与 `adv_model/X` 是彼此独立的条目，前者当裁判不影响后者当玩家。
- 上传失败会清除该侧旧 token，避免误用旧图；文件校验失败可重新选择同一文件。上传暂存由服务端按一天过期清理。
- 键盘可操作上传区和历史卡片；小屏使用单列图片布局，尊重系统减少动画偏好。

注意：本版本不提供历史文件删除按钮；JSON 可导出备份。历史列表当前在浏览器内筛选，尚未采用服务端分页。
