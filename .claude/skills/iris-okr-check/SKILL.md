# Iris OKR 双周逐项检查

对照 Q3 OKR 原文，从近两周的各类数据源中逐 KR 提取关键进展，输出结构化检查记录。

## 触发方式

用户说类似以下话语时，使用本 skill：

- "检查一下我OKR近两周的进展"
- "帮我做一下OKR双周逐项检查"
- "最近两周KR落地情况怎么样了"
- "看看Q3 OKR每个KR推进到什么程度了"

## 第一步：前置信息确认

在执行前先明确以下信息，如果用户未说明则默认：

| 项目 | 默认值 |
|:--|:--|
| 检查周期 | 最近两周（从当前日期往前推 14 天） |
| OKR 来源 | `SOURCE/01-目标管理/YYYY/` 中最新的个人 OKR 文件（01-目标管理 按年归档，最新文件在 `2026/` 子目录，文件名含本人姓名）|
| 检查对象 | OKR 中所有 KR（O1/O2/O3 共 10 个 KR）|
| 数据源 | 会议纪要 + 讨论思考 + 工作简报 + 我的周报 + 成员周报 |
| 输出目录 | `SOURCE/01-目标管理/YYYY/`（文件名 `YYYYMMDD-` 前缀自动归入年份子目录）|

## 第二步：读取 OKR 原文

找到 `SOURCE/01-目标管理/` 的年份子目录（如 `2026/`）下 `*OKR*` 最新的文件（通常文件日期最大的，文件名含本人姓名），完整读取：

- 提取 O1/O2/O3 的方向描述
- 提取每个 KR 的目标、Owner、KP 指标
- 记下每个 KR 的"KP"表格中的当前基线/目标值（后续据此判断进展）

## 第三步：扫描近两周数据源

基于检查周期确定起始日期和截止日期，扫描以下目录：

| 优先级 | 目录（含归档子目录） | 说明 |
|:--|:--|:--|
| P0 | `06-我的周报/YYYY/` | 你的双周报（两周内的最新 1-2 份，按年归档）|
| P0 | `05-会议纪要/YYYYMM/` | 日期落于周期内的全部会议纪要（按月归档）|
| P1 | `04-讨论思考/YYYYMM/` | 日期落于周期内的全部讨论记录（按月归档）|
| P1 | `07-成员周报/YYYYMM/` | w28/w29 等近两周周报（按月归档，关键核心成员的周报）|
| P2 | `09-工作简报/YYYYMM/` | 日期落于周期内的简报（按月归档）|

**确定检查周期**：如果用户指定了周期范围则使用指定范围；否则按当前日期往前推 14 天。例如当前 2026-07-22，则周期为 2026-07-08 ~ 2026-07-22。

**目录基准路径**：`${IRIS_WORK_DOCS_DIR}`（即 `.../WORKSPACE/SOURCE/`）。

## 第四步：逐个 KR 检查（核心流程）

共 3 轮，每轮一个 O 下的全部 KR，逐个 KR 独立处理。

### 每个 KR 的处理步骤

```
Step 1: 回顾 KR 原文 → 目标 + KP 指标 + 基线值
Step 2: 从全部数据源中 grep/逐份读取 → 定位该 KR 相关条目
Step 3: 提炼 → 一句话小结（高度概括的进展/风险/转折/延迟）
Step 4: 支撑 → ≤5 条细则（每条标注来源文件简称）
Step 5: 附加状态标记
```

### 状态标记规则

| 标记 | 含义 | 判断依据 |
|:--|:--|:--|
| 🟢 正常 | 按计划推进，里程碑按时或提前 | KP 指标正在达成路上，关键事件如期或提前 |
| 🟡 有风险 | 遇到阻碍或低于预期，但仍在推进 | 指标未达预期但仍在优化，或遇到可解决的问题 |
| 🔴 严重滞后 | 关键里程碑延迟，或方向性调整 | 上线延期、架构变更、指标远低于目标、方向被迫调整 |

### 细则写作规范

- 每条细则开头用 **粗体标注** 核心事件
- 每条结尾用 `（来源：文件简称）` 标注来源
- 细则之间按重要性或时间顺序排列
- 如果有具体数字指标，列出当前值（如"某 KP 指标达 XX%"）

### 检索策略（按 KR 分配）

针对不同的 KR，检索关键词要精准：

**O1-KR1**：核心品类/工艺环境/质量一致率/标注体系/新机型试点
**O1-KR2**：拆修检测/模型迭代/漏检/分类准确率
**O1-KR3**：二手商品/品牌覆盖/通过率/回收机制/品类扩展
**O2-KR1**：视频行为分析/动作识别/自研模型/成本
**O2-KR2**：在线校验/基础信息审核/成色分级/颜色识别/OCR
**O2-KR3**：作业流程/流程编排/留痕/场景接入
**O3-KR1**：智能巡检/搜索体验/badcase/准召率/分层解决
**O3-KR2**：流量倾向/商品品类/低价热销/特征工程/SKU
**O3-KR3**：人群划分/流量分配/首页保障
**O3-KR4**：搜索推荐基建/多模态/商品画像/AI Coding/PV

## 第五步：输出文档

### 文档命名

```
{YYYYMMDD}-OKR双周逐项检查记录.md
```
日期取提取截止日期（当天）。

### 输出路径

归档到 `SOURCE/01-目标管理/YYYY/`（按年归档子目录）。

### 文档结构要求

```markdown
# OKR 双周逐项检查记录

> **日期：** {YYYY-MM-DD}
> **检查周期：** {YYYY.MM.DD} — {YYYY.MM.DD}（近两周）
> **提取方式：** 从双周报、部门周会、项目周会、专项讨论、成员周报中逐 KR 检索提炼，LLM 辅助分析
> **提取人：** Iris 3.19

---

## O1：{方向标题}（N 个 KR）

### KR1：【标签】KR 标题

- **一句话小结：** [高度概括的进展/风险/转折]
- **状态：** 🟢 / 🟡 / 🔴
- **细则：**
  1. **{核心事件}**：{具体描述，含数据指标}（来源：{文件简称}）
  2. ...
  （最多 5 条，按重要度排序）

### KR2：...
```

## 第六步：交叉检查

全部 KR 完成后，做一轮整体质量检查：

1. **冲突检查**：同一事件在不同 KR 的描述是否矛盾（如某个结论在 KR1 说"已完成"，在 KR2 说"推进中"）
2. **歧义检查**：指标/结论是否有模糊表述（如"提升显著"而没有对比基线）
3. **重复检查**：跨 KR 的相同进展是否被重复展开（如有，在第一个出现的 KR 中留详尽描述，后续 KR 简略并注明"详见 KRx"）

检查结果写在文档末尾的 `## 交叉检查说明` 章节中。

## 第七步：展示摘要

执行完成后，在对话中展示一份简短摘要：

- 检查周期
- 检查覆盖的 O 和 KR 数量
- 每个 KR 的简要状态（如 O1-KR1 🟢, O1-KR2 🟡...）
- 整体结论（主要是哪个方向进展好、哪个方向有风险）
- 提醒用户已归档到 `SOURCE/01-目标管理/YYYY/`（按年归档子目录）

## 常见场景

| 用户说 | 操作 |
|:--|:--|
| "检查一下我OKR近两周的进展" | 默认最近两周，10个KR全量检查 |
| "只看O1方向" | 仅检查O1下的3个KR |
| "只看某个KR" | 仅检查指定的KR |
| "帮我对比一下前后两周" | 两次检查的结果做对比分析 |

## 与相关 Skill 的边界

- **`iris-report`**：双周报是"叙事型"报告，按方向写出战略分析和叙事；而 OKR 检查是"审计型"，逐 KR 对照原文检视进展
- **`iris-meeting`**：会议纪要的转录/归档；OKR 检查**消费**已归档的纪要，不产生新的纪要
- **`iris-daily-start`**：每日维护；OKR 检查是周期性审计，不替代日常维护
- 当用户说"检查OKR进展"、"OKR双周检查"、"看看KR推进"时，优先使用本 skill
