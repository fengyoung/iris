# Iris 招聘评估

从简历到面试方案：先判断候选人适合什么岗位、匹配多少，再生成一场能验证真实能力的面试方案。

> 所有命令均在 iris3 项目根目录执行（cwd = 仓库根目录）。

## 触发方式

- 「看看这份简历适合什么岗位」/「评估一下这份简历」
- 「按大模型算法岗评估这个候选人」（手动指定）
- 「给这个人生成面试方案」/「出一份面试提纲」
- 「他匹配我们的算法岗吗」

## 参考文件与岗位库（按阶段读）

| 文件 | 何时读 | 内容 |
|------|------|------|
| `data/hiring/job-catalog.md` | **阶段 2 必读** | 岗位 gate、维度权重、5 分锚点、红旗、溯源；**本地私有，不入仓** |
| `references/job-catalog.example.md` | 仅在私有库缺失时看 | 字段结构示例，**不能用于打分** |
| `references/scoring.md` | **阶段 2 必读** | 总分算法、职级档推断、AI 能力三档、档位阈值、置信度 |
| `references/interview-template.md` | **阶段 4 必读** | 标准/轻量双模板、篇幅上限、每题写作规则、合规禁问 |

**不得凭记忆打分或出题**——每次都要读岗位库与两个方法文件，尤其是岗位库可能已更新。

## 前置 · 岗位库准备

真实岗位标准库位于 `data/hiring/job-catalog.md`：本地私有数据，`.gitignore` 已忽略，**禁止提交到仓库**。首次使用或文件缺失时：

1. 按文末「重建岗位库」从 SOURCE 生成；
2. 找不到源报告就停下来问用户，**不要凭记忆编造岗位、权重或职级带**；
3. 仓库内的 `job-catalog.example.md` 只演示字段结构，不能替代真实标准。

## 阶段 1 · 简历归一化

按扩展名分流：

| 输入 | 处理 |
|------|------|
| `.md` `.txt` | 直接用 Read 工具读取 |
| `.pdf` `.docx` | `python3 scripts/run_cli.py --call-source skill process --image "<路径>" --query "提取简历全文，保留工作经历、项目、技术栈与量化结果"`（`process` **只从 `--image` 读文件**，`--input-file` 会被忽略、退化成纯文本处理）|
| `.doc`（旧格式） | 先让用户另存为 `.docx` 再走上一行；底层 `python-docx` 不支持 `.doc`，直接传会解析失败 |
| `.png` `.jpg` 等图片/扫描件 | `python3 scripts/run_cli.py --call-source skill process --image "<路径>" --query "识别简历内容"` |
| 用户直接粘贴文本 | 跳过本条，直接进下一步 |

产出**简历画像卡**（在对话中展示，供用户纠错）：

```
教育：{学历/专业/院校/毕业时间}
经历：{公司/职位/在职时间/一句话职责} × N
项目：{名称/角色/范围/技术栈/量化结果} × N
技能：{技术栈}
疑点：{表述含糊、范围不清、与常见要求冲突处}
```

疑点直接来自「无量化结果」「只写参与不写决策」「技术栈与岗位不符」等。这张卡是后续打分与出题的共同事实基础。

## 阶段 2 · 匹配打分

**先判定入口模式**：

| 用户是否指定岗位 | 模式 | 做法 |
|:--:|:--:|------|
| 未指定 | **A 自动匹配** | 全部岗位过 gate → 打分 → 排序，输出 Top 3 + 其余最高分 |
| 已指定 | **B 手动指定** | 按别名定位岗位 → 只评该岗 → 附错配提示（低 ≥15 分时） |

别名匹配不上时**必须列出相近岗位请用户确认，不得猜**。

两种模式都要产出：

```
岗位 | gate | 总分 | 档位 | 置信度 | 最强维度 | 最大缺口
```

外加一句「为什么是这个岗位」——引用岗位库里的 gate 与最高权重维度的匹配情况。

**职级档**：先按 `scoring.md` §四推断 L1/L2/L3，再取该档锚点评分。用错档会系统性误判（拿专家标准评校招生）。若候选人在岗位职级带之外，提示但不阻断。

## 阶段 3 · 目标岗位确认

- 模式 A 且 Rank 1 明确领先 → 默认取 Rank 1，列出备选供改判
- 模式 A 且 Top 1 与 Top 2 差 < 5 分 → **必须**说明差异维度并让用户选，不替用户决定
- 模式 B → 直接确认，记录「用户指定」及是否已提示错配

确认后告知将产出的规格（标准 60 min / 轻量 25 min，题目数、假设数）。

## 阶段 4 · 面试方案生成

读 `interview-template.md`，按 track 套模板。

生成顺序（不可颠倒）：

1. **先定假设**：从画像卡疑点中选 3 个（轻量 2 个），按模板 §六 的优先级挑——gate 潜在冲突 > n/a 维度 > 表述含糊
2. **再选题**：每假设至少 1 题；权重最高的两个维度各 ≥ 2 题；题量按 track 封顶
3. **排时间盒**：按模板的节奏表分配
4. **填评分卡**：维度与权重直接抄岗位库，5 分锚点截取，得分列留空给面试官
5. **写速查卡**：题号 + 关键词 + 红旗摘要 + 必问三句

**篇幅是硬约束**：标准 110–135 行（10–12 题），轻量 55–75 行（4 题）。超限按「先砍题、再压追问、不砍假设表与评分卡」处理。

## 阶段 5 · 自检与交付

按 `interview-template.md` §八 的八条自检逐条过一遍，重点：

- 每题是否绑定 `Hx` 或 `Dx`（绑不上的删）
- 是否含**合规禁问**（婚育/年龄/籍贯/民族/健康/家庭/财产）——这是红线，必须逐条扫
- 简历中的敏感个人信息（年龄、婚育、身份证、电话、薪资明细）是否被复述或用作判断依据

**输出落点**：

```
output/招聘/{YYYYMMDD}-{代号}-{岗位}-面试方案.md
```

`output/` 已 gitignore、不在数据源目录内、不进检索索引——**候选人信息与岗位库都不得写入 `SOURCE/`、仓库或任何会被 `scan-source` 扫描的目录**。

隐私约束：
- 只写代号（`C-01`）或用户给的简称，不写手机号、邮箱、住址、身份证、薪资明细；不复述简历原文，只引用判断所需的事实
- 岗位库只放 `data/hiring/`；不要把真实姓名、精确人数、职级带或部门结构写进仓库内的 Skill 文件

交付后在对话中给出：匹配度结论、目标岗位、方案路径、以及 2–3 个面试时要特别注意的点。

## 重建岗位库（可选分支，不作为默认流程）

仅当用户明确要求（如「组织调整了，更新岗位标准」「重新生成岗位库」）时执行：

1. 找到最新一份 `SOURCE/02-部门管理/**/*岗位类型与基本要求*.md`（按文件名日期取最大者）；找不到就停下来问用户
2. 按 `references/job-catalog.example.md` 的字段结构重新抽取：id / 名称 / 别名 / 岗位族 / 组织 / 人数 / 职级带 / track / gate / 维度权重 / 锚点 / 红旗 / 溯源。**不可只改数字**——人数、职级带、gate 都要重新核对报告原文
3. 同步更新 `references/scoring.md` §九 权重总表
4. 写入 `data/hiring/job-catalog.md`（本地私有，禁止入仓），更新头部 `catalog_version` 与 `rebuilt_from`
5. 向用户报告变更 diff（哪些岗位新增/删除/权重变化），**不静默覆盖**

## 与相关 Skill 的边界

| Skill | 关系 |
|-------|------|
| `iris-process` | **被本 skill 调用**，负责 PDF/DOCX/图片简历的文字与多模态抽取；`iris-hire` 只消费其输出，不重复实现解析 |
| `iris-ask` | 默认不调用。岗位标准已固化在岗位库中，检索式取要求会让评分口径漂移。需要查报告原文时人工直接读 |
| `iris-report` | 不复用。报告是叙事型长文，本 skill 要的是压缩到 100 行的裁判工具，优化目标相反 |

## 常见场景

| 用户说 | 操作 |
|------|------|
| 「看看这份简历适合什么岗位」 | 模式 A，全部岗位排序，出 Top 3 |
| 「按大模型算法岗评一下」 | 模式 B，只评 `ALG-LLM`，附错配提示 |
| 「他适合做算法还是测试」 | 模式 A，但结论聚焦这两类的对比 |
| 「直接出面试方案，不用分析匹配」 | 用户指定岗位则跳阶段 2 打分，仍要过 gate 与置信度 |
| 「这个人面试只有 30 分钟」 | 标准 track 短场（80–105 行 / 8–9 题） |
| 「标注员怎么面」 | 轻量 track，25 min / 4 题 / 2 假设 |
| 「面的是组长」 | `MGR`，管理五维，必须追问具体的人与事 |
