## 输出要求

返回严格的 JSON 对象（不要用代码块包裹）：

```json
{
  "direction_id": {{direction_id}},
  "direction_name": "方向名称",
  "high": [
    {"label": "文件引用标签", "reason": "简要说明为何高度相关（1句话）"}
  ],
  "medium": [
    {"label": "文件引用标签", "reason": "简要说明为何中度相关"}
  ],
  "low": [
    {"label": "文件引用标签"}
  ],
  "none": [
    {"label": "文件引用标签"}
  ]
}
```

判定规则：
1. **high**：文件核心内容直接讨论该方向的子领域、项目或指标 → 必读
2. **medium**：文件间接触及该方向（如讨论相关技术、相邻环节、上下游影响）→ 有参考价值
3. **low**：文件仅提了一两句话涉及该方向，实质性信息很少
4. **none**：与方向完全无关

**关键原则：按「首要话题」判定，不按「有没有提到」。**

**包容性规则（防止遗漏）**：当无法确定文件属于 low 还是 none 时，归入 low。当无法确定属于 medium 还是 high 时，归入 medium。宁可多保留，不可遗漏。一份文件即使只在一个子章节中讨论了与该方向相关的话题，也至少应归入 medium。

一份文件可能提到多个方向的概念，但只应对其**核心讨论的首要话题**判定为 high。例如：
- 一份讨论"图像采集3.0外观定级算法效果"的文件，即使提到了某流程优化方案或中心仓部署，其首要话题仍是「外观定级」→ 只对包含"验成色/图像采集3.0"的方向为 high
- 一份讨论"视频审核执行流程合规性"的文件，即使提到了 AI 识别准确率，其首要话题仍是「执行过程」→ 只对包含"视频审核"的方向为 high
- **不要因为文件"顺便提到"就归入 high 或 medium**，应严格按核心论题占比判定

注意：
- 每份文件必须出现在四个列表的某一个中，不能遗漏
- 判定基于**语义理解**而非关键词匹配——要理解文件在说什么、方向在关心什么
- 一份文件可能与多个方向相关（这由各方向的独立调用来判定，本次只判定对本方向的关联）
