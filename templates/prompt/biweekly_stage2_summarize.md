- 目录类型: {{dir_type}}

## 输出要求

返回严格的 JSON 对象（不要用代码块包裹）：

```json
{
  "label": "引用标签",
  "primary_direction": 1,
  "relevant_directions": [1, 3],
  "key_facts": [
    "关键事实1（一句话描述，含具体信息）",
    "关键事实2"
  ],
  "quantitative_data": [
    "指标名: 具体数值 / 变化量（如：支付转化率+6.52%）"
  ],
  "decisions": [
    "已做出的重要决策或明确的结论"
  ],
  "risks": [
    "暴露的风险、问题或阻塞点"
  ],
  "key_persons": ["涉及的关键人物姓名"],
  "strategic_insights": [
    "讨论/会议中形成的战略判断、方向性观点或决策依据（仅当 dir_type 为讨论思考类或「会议纪要」时填充，成员周报等例行汇报留空）"
  ],
  "brief_md": "## {{file_label}}\n\n### 关键事实\n- fact1\n- fact2\n\n### 量化数据\n- metric1\n- metric2\n\n### 决策与风险\n- 决策1\n- 风险1\n\n### 战略洞察（如有）\n- insight1"
}
```

规则：
1. **primary_direction**：该文件的核心首要方向（整数 ID）。文件可能涉及多个方向，但只有一个首要方向——判据是「文件 70% 以上的篇幅在讨论哪个方向的话题」
2. **relevant_directions**：该文件所有涉及的方向 ID 列表（含 primary）
3. **聚焦关联方向**：只提取与该文件被判定相关的方向有联系的信息，无关内容忽略
4. **Owner 优先提取**：关联方向中标注了子方向的「owner」。若文件的引用标签（label）或文件名中含有 owner 姓名，且文件中存在该 owner 所负责子方向的内容——即使篇幅不长——也应视为高优先级信息完整提取。这些内容是该子方向的一手进展汇报，不应因为文件其他章节篇幅更大而被忽略。
5. quantitative_data 必须包含具体数值，纯定性描述不放入此字段
6. 如果文件内容不包含某类信息（如无量化数据），对应字段返回空数组
7. brief_md 是综合摘要的 Markdown 格式，用于后续合成阶段
8. 保持事实准确——不添加原文中没有的信息，不推断
9. **strategic_insights**（讨论思考 + 会议纪要类专属）：当 dir_type 为讨论思考类（「讨论思考」「内部讨论」「独立沟通」「业务沟通」）或「会议纪要」时，额外提炼文件中的**判断与决策依据**——对某问题的归因判断、方向性结论、明确的取舍决策及其理由、会议中的关键分歧及收敛结果。每条约 1-2 句话，**提炼原文的判断与观点，而非复述事实过程**。这些洞察将直接注入双周报的总结段（思考→决策），是决策者视角的核心输入。成员周报（例行进展汇报）不填充本字段；成员周报的价值体现在 key_facts / quantitative_data 中。
