## 文件信息

- 目录类型: {{dir_type}}

## 输出要求

返回严格的 JSON 对象（不要用代码块包裹）：

```json
{
  "label": "引用标签",
  "primary_direction": 1,
  "relevant_directions": [1, 3],
  "key_facts": [
    "关键事实1（一句话描述，含具体信息）",
    "关键事实2"
  ],
  "quantitative_data": [
    "指标名: 具体数值 / 变化量（如：支付提袋率+6.52%）"
  ],
  "decisions": [
    "已做出的重要决策或明确的结论"
  ],
  "risks": [
    "暴露的风险、问题或阻塞点"
  ],
  "key_persons": ["涉及的关键人物姓名"],
  "strategic_insights": [
    "来自讨论/思考的战略判断或方向性观点（仅当 dir_type 为「讨论思考」或「内部讨论」时填充，其他类型可留空）"
  ],
  "brief_md": "## {{file_label}}\n\n### 关键事实\n- fact1\n- fact2\n\n### 量化数据\n- metric1\n- metric2\n\n### 决策与风险\n- 决策1\n- 风险1\n\n### 战略洞察（如有）\n- insight1"
}
```

规则：
1. **primary_direction**：该文件的核心首要方向（整数 ID）。文件可能涉及多个方向，但只有一个首要方向——判据是「文件 70% 以上的篇幅在讨论哪个方向的话题」
2. **relevant_directions**：该文件所有涉及的方向 ID 列表（含 primary）
3. **聚焦关联方向**：只提取与该文件被判定相关的方向有联系的信息，无关内容忽略
4. quantitative_data 必须包含具体数值，纯定性描述不放入此字段
5. 如果文件内容不包含某类信息（如无量化数据），对应字段返回空数组
6. brief_md 是综合摘要的 Markdown 格式，用于后续合成阶段
7. 保持事实准确——不添加原文中没有的信息，不推断
8. **strategic_insights**（讨论思考类专属）：当 dir_type 为「讨论思考」「内部讨论」「独立沟通」「业务沟通」时，额外提取文件中的战略判断、方向性观点、方法论思考。这些洞察将直接注入双周报的战略分析段，是决策者视角的核心输入。每条约 1-2 句话，提炼原文中的判断而非事实罗列。非讨论思考类文件（成员周报、会议纪要、方案报告）可留空。
